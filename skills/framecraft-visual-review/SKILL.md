# Framecraft visual review

Repository Markdown guide, not a provider-installed dependency. Read the selected scene's brief, then run `bun run review --project <path> --scene <id> --output <new-directory>` with optional `--milestone <shot:local-frame>`. Omit project/scene selectors for demo/intro, whose brief is inferred. Open **every** PNG listed in `manifest.json` individually, including both sides of each cut. Record factual findings by shot/local/global frame, or explicitly say no defect was observed against the brief. If a defect warrants an HTML fix, preserve the old artifact, change only the affected source, recapture into a **new** directory and inspect again. Only after inspection, edit the manifest's `review` status, named reviewer, findings and notes; run `bun run review --summary <manifest>` and `bun run review --check <manifest>` with the same project selection. The checker infers the captured scene from the manifest, but an explicit `--scene` must match. Neither capture, hash nor checker automatically judges visual quality. Do not claim human review unless a human performed it.

Studio accepts repeated `--review <capture-directory>` for verified matched-frame comparison. Persistent spatial issues live in a separate workspace, not historical manifests. Export JSON/Markdown with `bun run review:feedback`; verify source SHA and exact scene/shot-local frames before editing. See `docs/feedback.md` for conflict handling, stale issues and the provider-neutral handoff template. Never auto-resolve issues merely because source changed.
