# Phase 2: Frame-Based Audio Design

**Date:** 2026-10-22. **Status:** Approved design, pending written-spec review.

## Goal and scope

Add project-local background music and effects to the existing 330-frame demo, Studio and MP4 export without changing HTML shot authoring or the visual clock. No narration generation, TTS, cloud service, live video, transition, new mandatory dependency or rendering-engine rewrite. Supplied voice recordings can use the same cue schema when explicitly requested. Audio timing is frame-based, not a claim of sample-accurate or cross-machine-identical output.

## Manifest contract

`scene.audio` holds `{ "schemaVersion": 1, "cues": [...] }`. Each shot may hold `audio: [...]` using the same cue shape; these cues are relative to that shot's first frame and may not extend past its last frame. Scene cues are relative to scene frame zero. The old empty `scene.audio: []` remains accepted for silent projects with no shot cues; a nonempty legacy array or unknown schema version is an error. `project.audio` remains the existing empty array, and nonempty project-wide audio is rejected rather than ignored. No separate shot manifest is introduced.

A cue has required `id`, `src`, `startFrame`, `durationFrames`, `trimOutFrames`; optional `trimInFrames` (default 0), `gain` (default 1), `fadeInFrames` and `fadeOutFrames` (default 0), and `loop` (default false). `src` is relative to the project root (`assets/audio/bed.wav`, not a URL), and WAV and MP3 are the supported formats. `trimInFrames` and exclusive `trimOutFrames` delimit source frames at the project's fps; `durationFrames` is the number of output frames. Without `loop`, output duration must not exceed the trimmed source interval. With `loop`, only that source interval repeats until the output duration ends. Zero-based starts and nonnegative trims/fades are safe integers; durations and `trimOutFrames - trimInFrames` are positive safe integers. Gain is finite and between 0 and 1 inclusive; fades cannot exceed the cue duration and their sum cannot exceed it. For an output-local frame `f`, gain is the cue's gain times the clamped fade-in fraction `f / fadeInFrames` and fade-out fraction `(durationFrames - f) / fadeOutFrames`; a zero-length fade has factor 1. Thus fades are evaluated on scene frames even when source audio loops.

Every cue must fit within its containing shot or scene (`startFrame + durationFrames <= container duration`). All overlaps are permitted and mixed, including two effects over a music bed; there are no exclusive lanes or track names. Duplicate cue IDs within the same scene or shot are rejected; shot IDs scope their cue IDs. A missing file, a symlink escaping the project, unsupported extension or codec, undecodable media, and a trim beyond the probed source duration fail validation with a location and cue ID. Source media duration is probed before preview/export; conversion to available whole source frames uses the project's fps without making floating-point seconds authoritative for placement. Invalid projects cannot silently preview/export partial audio.

## Shared resolution and rendering

One pure timeline resolver maps cue starts to scene frames using validated shot offsets, retaining each cue's source range, playback duration, envelope and local asset URL. Both `loadStudioProject()` and `loadProject()` validate project-local assets and return this resolved timeline; Remotion's registered intro composition resolves the same manifest with the same pure function, rather than introducing a second interpretation of cue timing. The filesystem-dependent loader additionally checks actual media. For a shot-scoped still or export, only that shot's cues are included, now relative to shot frame zero; scene-wide cues are not implicitly sliced in.

`SceneComposition` renders HTML shot sequences and the resolved audio cues together. The existing `@remotion/player` and `renderMedia()` both use that component. Use installed Remotion audio support, project-local assets and frame-positioned sequences; calculate envelope gain from the composition's current integer frame. Remotion performs the overlap mix and MP4 encoding. No JavaScript timer, separate `<audio>` clock, or app-owned FFmpeg mixing. Player controls continue to own seeking, pausing, replaying and scene switching; switching scenes unmounts the former player's audio as well as its iframe. Browser autoplay and output-encoder limits are documented, not hidden.

The existing render command writes a process-specific `.partial-*` file and renames only after successful encoding and validation. Keep that atomic replacement boundary and remove the partial on any error. A failed audio render must leave a pre-existing successful MP4 unchanged. Silent scenes remain valid and export without a forced audio stream; a zero-gain cue must not change visual frames or cause export failure.

## Fixtures, tests and documentation

Provide small, locally generated PCM WAV music-bed and two distinct overlapping-effect fixtures, plus an MP3 format fixture, with a source recipe and clear rights/licensing note. The default demo remains 1920×1080, 30 fps, four shots, 330 frames; add scene and shot cues to make the default export audibly exercise both scopes. No external asset fetch.

Unit tests check scene/shot offsets, starts and ends, source trims, loop period, gain/fade boundary values and invalid overlapping fade/range constraints. Loader tests cover missing/out-of-project paths, symlinks, unsupported formats, duplicate IDs, bad codec or ranges and silent legacy manifests. An integration export must contain a scene music bed and two concurrent effects with distinguishable windows. Browser tests inspect audio playback position and paused state across seeking, pause/replay, and scene switching; allow bounded wall-clock tolerance without asserting sample precision. A failed-export test preserves an earlier file. Run all tests, typecheck, validate and the full 330-frame render; inspect audio/video streams independently with the available local probe and check that a silent fixture still renders. Update authoring and Studio/render docs and record actual verification and limitations in a Phase 2 report. Do not claim checks that were not performed.
