# ADR 0001: Use Remotion behind Framecraft's HTML-shot adapter

**Date:** 2026-10-21. **Status:** Accepted for Phase 0. **Score:** 3/4.

The [Phase 0 decision rule](../superpowers/specs/2026-10-21-phase-0-renderer-decision-design.md) selects Remotion at three or more passing criteria. The same three independent HTML shots were used throughout; none was rewritten as a React composition. Remotion handles encoding, composition, and frame capture; `projects/demo/runtime.js` and `src/spike/shot.tsx` translate shot-local frame requests into acknowledged iframe seeks. Remotion's `<IFrame>` alone does not synchronize CSS animation.

| Criterion | Result | Evidence |
| --- | --- | --- |
| Agent authoring | **PASS** | `AGENTS.md` describes one `window.framecraft.shot({prepare?,renderFrame,dispose?})` contract. The title, CSS+GSAP diagram, and closing HTML entries are independently loadable, with local assets and no Remotion imports. |
| Determinism | **PASS** | `bun test` runs a browser test of the standalone diagram at 70 → 10 → 70 and a separate Remotion Player test of the adapter at 70 → 10 → 70 in one page; first/last PNG bytes match, while frame 10 differs. Separate `bun run snap --frame 70 --shot diagram` processes produced the same SHA-256 `62f15b98d4cf69adf6aacf8355fed49222fff830954968d966a7b55dc343fb0e`. Browser, JS libraries, and frame rate are pinned. |
| Weight and licensing | **FAIL** | Installed `node_modules` is ~972 MiB on this Linux machine, including a 236 MiB pinned Chromium and 27 MiB compositor package. Bun 1.4.3 and `bunx remotion browser ensure` are needed. [Remotion's license](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md) is free for individuals, nonprofits, evaluation, and for-profit teams up to three; larger operators need a Company License. [Automation licensing terms](https://www.remotion.dev/docs/license/faq) must be reviewed before agent-driven commercial operation. This is a meaningful packaging and legal constraint, not an unconditional free local engine. |
| Control | **PASS** | `bun run snap --frame 70 --shot diagram` produces a PNG; `bun run render --shot diagram` produces a 90-frame MP4; the original three-shot `bun run render` produced a schema-validated 210-frame MP4 (the current four-shot demo is 330 frames). `loadProject()` rejects duplicate IDs, invalid durations, nonzero overlap, missing/out-of-root entries, and symlinks escaping the project. Frame acknowledgement, cancellation, timeouts, and browser errors fail the operation. No renderer internals are replaced. |

Measured on the Phase 0 Linux host (including bundling; not a benchmark): scoped 90-frame H.264/yuv420p export took 16.81–19.80 s across two runs, output 51,658 bytes, peak parent-process RSS 583,124 KiB in the measured run; full 210-frame 1920×1080@30 export took 24.15–27.11 s across two runs, output 115,167 bytes, peak parent-process RSS 658,796 KiB in the measured run. `ffprobe -count_frames` reported exactly 90 and 210 video frames respectively; the full video is 7.0 s at 30 fps. `/usr/bin/time` reports the parent command's RSS, not aggregate Chromium/FFmpeg memory. Repeated frame-70 stills took 9.08 s and 6.09 s including separate bundling/browser starts; these are not per-frame render timings. Simple, low-motion demo graphics compress unusually well; sizes do not predict real-project output.

**Consequences:** Keep manifests and the HTML shot API Framecraft-owned. Pin the browser and Remotion packages, and keep the licensing check explicit for each deployment. The runtime freezes shot clocks and rAF timestamps, seeds `Math.random`, seeks CSS/WAAPI and both registered and legacy paused GSAP timelines, and serializes overlapping seeks so obsolete frames do not acknowledge. Bundled OFL WOFF2 fonts replace system-font first choices; it flushes layout, waits for fonts, image decoding, two native animation frames and rechecks font readiness before acknowledging. Browser tests cover reverse and overlapping seeks, progress boundaries, both timeline APIs, a delayed real font, and image settlement. The expanded twelve-frame hash report matched in two successive local runs; the first expanded-report run was not retained for a per-frame comparison. `bun run validate` emits nonfatal source warnings, not a proof of safety. This does not prove arbitrary JS side effects, timer-driven state (`setInterval`/`setTimeout` remain live), live video, audio, transitions or cross-machine pixel identity: no second-machine comparison has run. `renderFrame` should set the complete state for a frame; resources with their own clocks need dedicated coverage before production use. A `?scene=` preview/deep link and Studio UI were not built in this Remotion decision spike; the preview requirement appears in the design's in-house branch and remains future work. Do not start the in-house engine on the strength of this spike: 3/4 passes select Remotion.
