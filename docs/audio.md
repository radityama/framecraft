# Audio authoring

Declare audio in `projects/demo/scenes/intro/scene.json`, not in HTML shots. Scene cues start at scene frame zero; a shot's `audio` array starts at its own frame zero. For example, the demo's scene bed and a looping shot effect:

```json
{
  "audio": {"schemaVersion": 1, "cues": [
    {"id": "bed", "src": "assets/audio/bed.wav", "startFrame": 0,
     "durationFrames": 330, "trimOutFrames": 330, "gain": 0.35,
     "fadeInFrames": 6, "fadeOutFrames": 12}
  ]},
  "shots": [
    {"id": "diagram", "entry": "shots/02-diagram/index.html",
     "durationFrames": 90, "overlapFrames": 0,
     "audio": [{"id": "hit-b", "src": "assets/audio/hit-b.wav",
       "startFrame": 15, "durationFrames": 24, "trimOutFrames": 20,
       "gain": 0.6, "loop": true}]}
  ]
}
```

This excerpt omits the other scene shots and cues. The full manifest is in `projects/demo/scenes/intro/scene.json`. `project.audio` is reserved and must stay empty. An old `scene.audio: []` is allowed only for a silent scene with no shot audio; otherwise use `{ "schemaVersion": 1, "cues": [...] }`. Nonempty legacy arrays and other schema versions fail validation. Cue IDs are kebab-case and unique within their scene or shot; shot IDs scope them. Overlapping cues mix freely, including effects on top of the bed.

Each cue requires `id`, `src`, `startFrame`, `durationFrames`, and `trimOutFrames`. `trimInFrames` defaults to 0; `gain` defaults to 1; `fadeInFrames` and `fadeOutFrames` default to 0; `loop` defaults to false. Frames are zero-based integers at the project's 30 fps. `startFrame` is the destination frame, and `durationFrames` is the number of frames played. `trimInFrames` is inclusive and `trimOutFrames` **exclusive** in the source: `[trimInFrames, trimOutFrames)`. Without `loop`, the output duration must fit in that source interval; with `loop`, only the trimmed interval repeats until `durationFrames` elapses. A shot cue cannot outlast its shot; a scene cue cannot outlast its scene. A shot-only export includes that shot's cues, not scene cues: the title export is silent and the close shot has a zero-gain cue.

`gain` is finite between 0 and 1 inclusive. For a cue-local output frame `f`, the envelope is `gain × clamp(min(1, f / fadeInFrames, (durationFrames - f) / fadeOutFrames), 0, 1)`; a zero-length fade contributes factor 1. Fade lengths are nonnegative and cannot sum to more than the cue duration. The envelope follows output frames, even during a source loop. A zero-gain cue is valid and produces silence (the encoder may still emit an audio stream). Placement, trims, repeats and gain are frame-based, **not** sample-accurate or cross-machine-identical guarantees.

`src` must point to a local project asset, for example `assets/audio/hit-a.mp3`; URLs, paths outside the project and escaping symlinks are rejected. Supported inputs are PCM WAV (`.wav`) and MP3 (`.mp3`); a matching extension alone is insufficient. Loading a project probes the codec and source duration with Remotion's bundled FFprobe, decodes to a null sink to reject bad media, and checks trims before preview or export. Remotion handles playback and mixing, not the HTML iframe or a separate Studio clock. Browsers may block autoplay before user interaction. The synthetic tone fixtures in `projects/demo/assets/audio/` are generated by `bun scripts/generate-audio-fixtures.ts` without third-party recordings and released under CC0 1.0; see their `LICENSE.md`. They are diagnostic sounds, not production music.

Run `bun run validate` to check the project, `bun run studio` to preview, or `bun run render` for the full MP4. Use `bun run render --shot diagram` for just the diagram and `bun run render --output /path/to/intro.mp4` to choose a destination. See [Rendering](rendering.md) for stream inspection and [Phase 2 results](audio-phase2-report.md) for observed verification.
